## Multi-Genome Workflow Design

### User Requirements Captured
- 5 genomes: HG002 (has v5q for optimization) + 4 others (HG008N/T, NA12878, HG005)
- HG002 param optimization → pick winners → apply to 4 other genomes
- Cross-genome comparison identifies discrepancy hotspots
- Iterative refinement (future): use WGS platform data to characterize errors

### Workflow Stages
1. **HG002 sweep** - Generate 18-27 analyses with parameter cross-products
2. **HG002 scoring** - Compare to v5q, rank by F1/precision/recall
3. **Top-N selection** - Pick 3-5 best parameter sets  
4. **4-genome validation** - Apply winners to other genomes (36-45 analyses)
5. **Cross-genome analysis** - Identify consistent winners + outliers

**Documented in:** `docs/design/v0.023-parameter-optimization-design.md`

## Technical Decisions

### What We're Following (Proven Patterns)
- VCF processing profiles (config/resources.yml:152-192)
- Truvari bench params (config/resources.yml:89-115, scripts/truvari_params.py)
- Schema validation (schema/resources-schema.yml)

### What We Fixed
- Dipcall params: Now actually works (was completely broken)

### What We're Avoiding (Over-Engineering)
- Abstract base classes for parameters
- Separate builder scripts per tool
- Complex dependency resolution
- Auto-detection heuristics
- Wrapper scripts that just glue 2 calls

### What We're Adding (Under-Engineering Safeguards)
- Upfront validation (fail fast, not 6 hours later)
- Dry-run modes
- Cost estimation
- Explicit error messages
- Schema bounds checking
