# V0.023 Parameter Optimization Framework - Design

**Date:** 2026-07-21  
**Status:** Approved after adversarial review  
**Workflow:** 3-phase design with over/under-engineering critique

---

## Executive Summary

Extends DeFrABB's parameter infrastructure to support systematic parameter sweeps for multi-genome benchmark optimization. Four independent components:

1. **Parameter Profile Registry** - Named profiles for all pipeline params (dipcall, PAV, exclusions)
2. **Sweep Generator** - Declarative YAML → analyses table with cross-products  
3. **v5q Baseline Comparison** - Enhanced compare_evaluations.py with scoring/ranking
4. **Output Reuse** - Snakemake patterns to share expensive variant calls

**Validated by adversarial review:**
- Over-engineering critique: Removed helper classes, simplified abstractions
- Under-engineering critique: Added validation, error handling, observability
- Final design balances robustness with simplicity

---

## Design Principles (Critique-Driven)

✅ **Keep (from over-engineering review):**
- Build on proven patterns (VCF profiles, Truvari params work well)
- Minimal core pipeline changes
- Each component independently useful
- Clear separation of concerns

✅ **Add (from under-engineering review):**
- Schema validation for all new configs
- Explicit error messages for common failures
- Dry-run mode for sweep generator
- Sanity checks on cross-products (detect explosions)

❌ **Remove (over-engineered):**
- Abstract "ParameterProfile" base class (1 use case)
- Separate builder classes for each tool (just use functions)
- Complex dependency resolution (Snakemake already does this)

## Component 1: Parameter Profile Registry

### Purpose
Centralize all tunable parameters with named profiles. Fixes broken dipcall params; unifies PAV, exclusions with working VCF/Truvari patterns.

### Implementation

**Files to create/modify:**
- `config/resources.yml` - Add profile sections
- `scripts/param_helpers.py` - Profile lookup functions
- `schema/resources-schema.yml` - Validation patterns
- `.tests/unit/test_param_profiles.py` - Profile tests

**Pattern (from working Truvari params):**
```yaml
# config/resources.yml
_dipcall_params:
  z2k: "-z200000,10000"
  z5k: "-z500000,5000"
  z10k: "-z1000000,10000"

_pav_params:
  giab: {merge_ins: "nr::exact", merge_del: "nr::exact"}
  strict: {merge_ins: "nr::szro(0.9,100)", merge_del: "nr::exact"}

_exclusion_profiles:
  conservative: {slop: 15000, slopmerge_dist: 10000}
  standard: {slop: 10000, slopmerge_dist: 5000}
  aggressive: {slop: 5000, slopmerge_dist: 3000}
```

**Rule changes (minimal):**
```python
# rules/asm-varcall.smk - dipcall fix
params:
    extra=lambda w: config["_dipcall_params"].get(
        w.vc_param_id, 
        vc_tbl.loc[w.vc_id]["vc_params"]  # fallback
    )
```

**Validation (from under-eng critique):**
- Schema patterns enforce format (e.g., dipcall must match `-z\d+,\d+`)
- Unknown profile name → clear error message
- Required profiles (default) checked at load time

## Component 2: Parameter Sweep Generator

### Purpose
Declarative YAML → analyses table TSV with cross-product generation. Enables 50-100 analysis sweeps without manual editing.

### Implementation

**Files:**
- `scripts/generate_param_sweep.py` - Generator script
- `config/sweeps/*.yml` - Sweep definitions
- `.tests/unit/test_sweep_generator.py` - Tests

**Sweep YAML format:**
```yaml
# config/sweeps/hg002_smvar_opt.yml
name: HG002 Small Variant Optimization
output: config/analyses_20260721_v0.023_hg002_smvar_sweep.tsv

# Fixed across all analyses
fixed:
  ref_id: GRCh38
  asm_id: HG2-T2TQ100-V1.1
  vc_cmd: dipcall
  bench_type: smvar
  eval_cmd: happy
  eval_comp_id: v5.0q-smvar

# Generate cross-product
sweep:
  vc_param_id: [z2k, z5k, z10k]
  exclusion_profile: [conservative, standard, aggressive]
  vcf_processing: [trf, xy_trf, norm_xy_trf_sv_lcr]

# Optional constraints
constraints:
  - if: {bench_type: stvar}
    then: {vcf_processing: [norm_xy_trf_sv_lcr]}
```

**Cross-product:** 3 × 3 × 3 = 27 analyses

**Safety features (from under-eng critique):**
- `--dry-run` flag: print count + first 3 rows without writing
- Max analyses limit (default 200): fail if cross-product > limit
- Schema validation: output TSV validated before write
- Sanity warnings: "27 analyses will take ~162 compute-hours (6h × 27)"

**Usage:**
```bash
scripts/generate_param_sweep.py \
  config/sweeps/hg002_smvar_opt.yml \
  --dry-run  # check before committing

scripts/generate_param_sweep.py \
  config/sweeps/hg002_smvar_opt.yml \
  --max-analyses 100  # safety limit
```

## Component 3: v5q Baseline Comparison & Scoring

### Purpose
Score experimental parameters against HG002Q100v5 baseline. Identify regressions and rank by optimization metric.

### Implementation

**Enhance `scripts/compare_evaluations.py`:**

**New flags:**
- `--v5q-baseline`: Auto-detect v5q in results, compute deltas
- `--rank-by {f1,precision,recall}`: Sort by metric descending  
- `--threshold 0.001`: Min delta to flag regression/improvement

**Output example:**
```
| analysis_id         | variant_type | f1     | delta_f1 | status    |
|---------------------|--------------|--------|----------|-----------|
| v5.0q-smvar         | SNP          | 0.9987 | --       | baseline  |
| z5k_aggressive_trf  | SNP          | 0.9991 | +0.0004  | improved  |
| z2k_standard_trf    | SNP          | 0.9986 | -0.0001  | same      |
| z10k_conservative   | SNP          | 0.9975 | -0.0012  | regressed |
```

**Helper script:**
```bash
# scripts/score_param_sweep.py - wrapper for common workflow
scripts/score_param_sweep.py \
  --sweep-dir 20260721_v0.023_hg002_sweep \
  --top-n 3 \
  --out sweep_summary.md

# Outputs:
# - Top 3 by F1, precision, recall
# - Recommended param sets for validation round
# - Warnings for regressions
```

**Error handling (from under-eng critique):**
- Missing v5q baseline → clear error + suggest baseline location
- Empty results dir → helpful message
- No regressions found → success message (not silent)

## Component 4: Output Reuse Infrastructure

### Purpose
Share expensive variant calls (dipcall 3-6h, PAV 4-8h) across parameter sweeps when only downstream params change.

### Current State (Good News!)
**Snakemake already handles this via vc_id encoding:**
- `vc_id = f"{ref}_{asm}_{vc_cmd}-{vc_param_id}"`
- Same vc_id → same outputs → automatic reuse

### What We Add
**Sweep generator intelligence:**
```python
# scripts/generate_param_sweep.py
def assign_vc_ids(analyses):
    """Group analyses by (ref, asm, vc_cmd, vc_param_id), assign shared vc_id"""
    groups = {}
    for row in analyses:
        key = (row['ref_id'], row['asm_id'], row['vc_cmd'], row['vc_param_id'])
        if key not in groups:
            groups[key] = f"vc{len(groups) + 1}"
        row['vc_id'] = groups[key]
    
    # Log reuse stats
    unique_calls = len(groups)
    total_analyses = len(analyses)
    reuse_factor = total_analyses / unique_calls
    log(f"Output reuse: {unique_calls} variant call runs for {total_analyses} analyses")
    log(f"Reuse factor: {reuse_factor:.1f}x (saves ~{(total_analyses - unique_calls) * 6}h)")
```

**Example:**
- 27 analyses (3 vc_params × 3 exclusions × 3 vcf_processing)
- Groups: 3 vc_params × 1 asm × 1 ref = 3 dipcall runs
- Reuse factor: 27 / 3 = 9x
- Time saved: 24 × 6h = 144 hours

**No rule changes needed** - Snakemake does the work!

## Multi-Genome Workflow

### Scenario: 5-Genome Parameter Optimization

**Genomes:**
1. HG002 (has v5q baseline for optimization)
2. HG008-Normal, HG008-Tumor (comparable callsets available)
3. NA12878, HG005 (GIAB samples with comparison data)

### Workflow Stages

**Stage 1: HG002 Parameter Sweep**
```yaml
# config/sweeps/hg002_optimization.yml
fixed:
  ref_id: GRCh38
  asm_id: HG2-T2TQ100-V1.1
  eval_comp_id: v5.0q-smvar

sweep:
  vc_param_id: [z2k, z5k, z10k]
  exclusion_profile: [conservative, standard, aggressive]
  vcf_processing: [trf, xy_trf]
  eval_params: [default]

# Output: 18 analyses (3×3×2), ~12 dipcall runs with reuse
```

**Stage 2: HG002 Scoring**
```bash
scripts/score_param_sweep.py \
  --sweep-dir 20260721_HG002_opt \
  --top-n 3

# Output identifies top 3 param sets:
# 1. z5k + aggressive + xy_trf (F1: +0.0004, Precision: +0.0002)
# 2. z2k + standard + trf (F1: +0.0001, Recall: +0.0003)
# 3. z10k + conservative + xy_trf (F1: -0.0001, Precision: +0.0005)
```

**Stage 3: 4-Genome Validation**
```yaml
# config/sweeps/validation_4genome.yml
fixed:
  ref_id: GRCh38
  vcf_processing: xy_trf  # from winner

sweep:
  asm_id: [HG008N-T2TQ100, HG008T-T2TQ100, NA12878-T2T, HG005-T2T]
  vc_param_id: [z5k, z2k, z10k]  # top 3 from HG002
  exclusion_profile: [aggressive, standard, conservative]

# Output: 4 × 3 × 3 = 36 analyses
```

**Stage 4: Cross-Genome Analysis**
```bash
# Compare metrics across all 5 genomes
scripts/compare_evaluations.py \
  --results-dir validation_run \
  --regions \  # BED stats
  --group-by vc_param_id \
  --out cross_genome_comparison.tsv

# Identifies:
# - Parameter set with best cross-genome consistency
# - Genome-specific outliers (flag for review)
# - Stratifications with high discrepancy rates
# - Excluded regions with unexpectedly high concordance
```

**Stage 5: Iterative Refinement (Future)**
- Use discrepancy hotspots to refine exclusions
- Add WGS platform data for error characterization
- Update benchmark regions based on evidence
